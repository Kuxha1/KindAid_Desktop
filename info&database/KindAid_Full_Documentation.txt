================================================================================
1. PROJECT VISION & SCOPE
================================================================================

The KindAid: Donation & Service Contribution System addresses a critical gap in 
charitable networking. By unifying NGOs, volunteers, and private citizens onto a 
single platform, the system prevents siloed charity efforts. 

Its primary mission is to:
- Connect donors directly with verified fundraisers.
- Provide geographical visibility of immediate service and material needs.
- Foster community discourse between verified NGOs and everyday volunteers.
- Provide real-time data monitoring for platform administrators.

================================================================================
2. HIGH-LEVEL ARCHITECTURE & TECH STACK
================================================================================

The project operates strictly over a Client-Server Architecture (REST).

2.1 Frontend: Mobile Application (Flutter)
- Language: Dart
- State Management: Uses structured Models and Providers to handle system states.
- Network Layer: Uses the `http` package directed through `lib/core/api_service.dart`.
- File Uploads: Uses `image_picker` and HTTP Multi-part formatted requests.
- Maps: Integrates `google_maps_flutter` SDK with platform API keys.

2.2 Frontend: Web Dashboard (Admin Panel)
- Structure: HTML5 semantics, CSS3, Vanilla JavaScript.
- Backend Engine: Vanilla PHP 8+ handling Session logic and API routing.
- Responsive Logic: Custom CSS utilizing CSS Grid, Flexbox, media queries.
- UI Capabilities: Chart rendering for metrics, AJAX calls for non-blocking UI.

2.3 Backend API / Server
- Language: PHP (REST API Frameworkless)
- Role: Processes SQL queries, validates user data, sanitizes inputs, responds 
  exclusively in JSON format.
- Authentication: Secure password hashing (bcrypt), PHP-based Session handling 
  for web, and ID-tokening / OTP generation for mobile login.
- Email Server: Integrated PHPMailer for secure OTP delivery to verified emails.

2.4 Database (MySQL: `kindaid.sql`)
- Engine: InnoDB (for complex mapping and Foreign Key constraint handling).
- The exact same relational database is accessed by the PHP Web interface and 
  the PHP REST API, ensuring 0% data lag/desync between app and website.

4. CORE USER ROLES & PERMISSIONS MATRIX
================================================================================

4.1 Users (Standard Accounts)
- Registration: Name, Email, Address, Password. Verified via Email OTP.
- Capabilities: 
  * Post in Community
  * Create Need Requests (e.g. "I need 10 blankets")
  * Pin points on Geo-Visibility map
  * Donate to Fundraisers (Update fundraiser current amounts)
  * AI Chatbot Assistance

4.2 NGOs (Organization Accounts)
- Registration: Same as Users + REQUIRED upload of 2 Verification Documents.
- Verification State: Initially marked as "Pending" in the database. Once Admin 
  flags as "Verified", the NGO receives a badge.
- Capabilities: 
  * All standard user abilities.
  * Start large scale financial Fundraisers.
  * Appear distinctly on the Geo-Map as an Organizational Hub.

4.3 System Admin (Web Only)
- Registration: Pre-seeded into DB (Cannot be registered publicly).
- Capabilities:
  * Approve / Reject NGO Documents.
  * Ban / Delete Accounts violating ToS.
  * Moderate and Delete any Post, Fundraiser, or Geo-Pin.
  * View backend metric dashboards.

5. DETAILED FEATURE SPECIFICATIONS (MOBILE & WEB)
================================================================================

5.1 Authentication Flow (OTP)
1. User submits data. Backend creates an OTP and stores it transiently.
2. PHPMailer dispatches a customized HTML email containing the OTP.
3. Mobile app opens OTP screen. User submits OTP.
4. If correct, the account is activated, and JSON login payload returns to app.

5.2 Community Forum Workflow
- Flutter App requests GET `/community/get_posts.php`.
- UI renders a feed using modern `post_card` Shimmer loading layouts.
- Users can upload up to 2 images. Flutter compresses these images via plugin 
  before transmission.
- API accepts `multipart/form-data`, saves files to relative `/uploads/` dir, 
  and inserts DB record.

5.3 Fundraisers & Need Models
- Unlike Forum Posts, Fundraisers have mathematical bounds (`current_amount` <= `target`).
- Mobile UI presents an Animated Progress Bar based on `(current/target) * 100`.
- Only authors of the content see "Edit/Delete" widgets inside the detail screen 
  (Feature parity validation checking `currentUser.id == post.owner_id`).

5.4 Geo-Visibility Map
- Implements `google_maps_flutter`. 
- Upon map initialization, Flutter fetches GET `/geo/get_locations.php`.
- The map renders custom markers: Purple for Verified NGOs, Orange/Red for 
  urgent Needs.
- Tapping a marker expands a BottomSheet revealing photos, description, and an 
  actionable button (e.g., "Help Now").

6. API DESIGN & SECURITY STANDARDS
================================================================================
API Path Configuration: All API requests hit `http://{server_ip}/KindAid/api/...`

Security Standards:
- Standardized Output: API scripts strictly header as `application/json`.
- Fail-Safes: PHP endpoints validate `empty()` against all $_POST fields.
- Type Safety: Mobile app parses JSON into statically-typed Dart classes 
  (e.g., `UserModel`, `FundraiserModel`) to prevent runtime null errors.
- Image Handling: API assigns unique unix timestamps to filename uploads to 
  prevent overwriting (`time()_filename.jpg`).

Sample Endpoint Map:
- POST `/auth/register.php` (Creates user)
- POST `/auth/login.php` (Validates and returns User Data)
- POST `/auth/send_otp.php` (Fires PHPMailer)
- GET `/feed/get_all.php` (Retrieves generic posts)

8. AI INTEGRATION SPECIFICS (GEMINI CHATBOT)
================================================================================

Intent: A smart virtual helper for users to query platform data and navigate.
Location: Accessed via a Floating Action Button in the mobile profile screen.

Capabilities & Architecture:
- Provider: Google Gemini AI (REST API via Dart).
- Local Integration: The NLP engine is built into the Flutter app (`api_service.dart`).
- Data Flow:
  1. User asks: "Are there homeless shelters nearby?"
  2. Flutter sends Context Window prompt + User Query to Gemini.
  3. Context Window tells Gemini to behave as KindAid Assistant, format its 
     response, and trigger internal routing if the user asks for DB-heavy data.
  4. If Gemini fails or context is too localized, the chatbot falls back to 
     a local PHP API query to parse simple DB parameters.
- UI Design: Renders custom chat bubbles, interactive chips ("Show me NGOs", 
  "Navigate to Profile"), and shimmer loading while awaiting the AI.

9. DEPLOYMENT, LOCAL SETUP, & SYNCHRONIZATION
================================================================================

9.1 Database Unification Architecture
- The absolute rule of KindAid is Single-Source-of-Truth. 
- Mobile and Web MUST use the identical database instance.

9.2 Step-by-Step Developer Setup
1. Mount XAMPP. Drop `KindAid` folder into `C:/xampp/htdocs/`.
2. Secure the database: Open phpMyAdmin -> Import `kindaid.sql`.
3. Check web application connection via `http://localhost/KindAid/admin`.

9.3 Connecting Flutter Device to Backend
- **For Android Studio Emulator:**
  Open `api_service.dart` -> Set `baseUrl = 'http://10.0.2.2/KindAid/api/'`
  (10.0.2.2 routes local emulator traffic back to the XAMPP host).
  
- **For Physical Android/iOS Device:**
  Open Windows CMD -> type `ipconfig`. Find IPv4 Address (e.g., 192.168.1.x).
  Open `api_service.dart` -> Set `baseUrl = 'http://192.168.1.x/KindAid/api/'`.
  Ensure Firewall allows port 80 (Apache).
